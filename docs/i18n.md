# Internationalisation (i18n)

VideoWipe ships its user interface and server messages in Simplified Chinese
(zh-CN). This repository is a fork that keeps merging from upstream
(`KKenny0/videowipe`), so the i18n design is built to minimise merge
conflicts and to tolerate new upstream strings without breaking anything.

## How it works: a source-text-keyed overlay

We do **not** replace Chinese strings in `index.html` or the server code with
translation keys. The upstream sources keep their original text; translation
happens at presentation time, in the style of `gettext`.

A **catalogue** is a JSON mapping from the exact zh-CN source string (the
*key*) to a translation (the *value*):

```json
{
  "_meta": {"language": "en", "name": "English", "source_language": "zh-CN"},
  "messages": {
    "试擦 {0}–{1}": "Trial wipe {0}–{1}",
    "取消处理": "Cancel processing"
  },
  "obsolete": {}
}
```

Two rules make the overlay safe:

- **zh-CN is the source language.** There is no zh-CN catalogue; for the source
  language `translate()` is the identity function.
- **An empty value (`""`) or a missing key means "untranslated".** The
  presentation layer falls back to the original Chinese. A new upstream
  string therefore never breaks the UI — it simply appears in Chinese until
  it is translated.

`zh-CN` strings are detected by the presence of CJK characters
(U+3000–U+303F, U+3400–U+9FFF, U+FF00–U+FFEF). Non-CJK text is always left
as-is.

### Placeholders

Interpolated parts are written `{0}`, `{1}`, … in **both** the key and the
value, e.g. `"试擦 {0}–{1}": "Trial wipe {0}–{1}"`. A value may reorder
placeholders, but the *set* of placeholders must match its key — `make
i18n-check` fails otherwise.

### The translation algorithm

`translate(text, messages)` (implemented identically in Python and JS)
works on the trimmed core of the string, preserving surrounding whitespace:

1. If the text has no CJK character, return it unchanged.
2. **Exact match** — if the trimmed text is a key with a non-empty value, use it.
3. **Pattern match** — for keys containing `{n}`, build an anchored regular
   expression (literal parts escaped, each `{n}` a lazy group) and try the
   patterns longest-first; on a match, translate each captured group
   recursively and substitute into the value. Keys with *adjacent*
   placeholders (`{0}{1}…`) cannot be split reliably and are skipped.
4. **Fragment fallback** — scan left to right for plain keys occurring as
   substrings and for *bounded* pattern keys (ones that start and end with
   literal text, e.g. `· 当前阶段 {0}%`) occurring anywhere; the earliest match
   wins, then the longest. This handles JS concatenations such as
   `"需留意：" + warnings.join("；")` and suffixes appended with `+=`.
   Because Chinese has no spaces between words, a space is inserted wherever
   two translated pieces would otherwise join letter-to-letter
   (`"移除" + name` → "Remove Bottom subtitles").

### Hand-added fragments (`extra`)

Sometimes upstream only builds a phrase by concatenation, so a piece such as
`区域` never appears on its own and is never extracted. Add such pieces to an
optional `"extra"` object in the catalogue:

```json
"extra": {"区域": "area"}
```

`extra` entries are used by the runtime exactly like `messages` (a non-empty
`messages` entry wins on conflict), and `make i18n-sync` never adds, moves or
drops them. Keep them few and short, and check that every context in which
the fragment occurs still reads well.

The exact, shared behaviour is pinned by the test vectors in
`tests/fixtures/i18n_vectors.json`; both the Python and the JS
implementations must pass every vector.

## How it is wired in

The fork touches upstream files in only two places, so upstream merges and
other fork branches rarely conflict with it:

- **Web UI** — one line after `app = FastAPI(...)` in `server/app.py` calls
  `videowipe.i18n.install(app)`. It adds a middleware that injects the
  catalogue and `web/i18n.js` into the page served at `/`; the upstream
  index route and `index.html` are unchanged.
- **CLI** — `pyproject.toml` points the `videowipe` command at
  `videowipe.i18n_cli:main`, which runs upstream's `videowipe.cli.main` with
  stderr translated line by line. Only whole messages are translated (exact or
  pattern matches, an optional `videowipe: ` prefix kept), so file names and
  paths are never rewritten. After changing the entry point, reinstall
  (`pip install -e .`) so the `videowipe` command picks it up;
  `python -m videowipe.cli` runs untranslated.

## Language selection

- **Web** — in order: a `?lang=<code>` query parameter, the `videowipe.lang`
  `localStorage` value, then the first `navigator.languages` entry whose
  prefix matches an available locale (any `zh` prefix maps to zh-CN). The
  default is `en`.
- **Python / CLI** — in order: the `VIDEOWIPE_LANG` environment variable, then
  `LC_ALL`/`LC_MESSAGES`/`LANG` (a `zh` prefix maps to zh-CN, `en` to en).
  The default is `en`.

## File layout

```
src/videowipe/locales/
├── ignore.json     # what the extractor must skip
├── en.json         # English catalogue (one file per locale)
└── <lang>.json     # …
scripts/i18n_sync.py # the extraction / sync / check / translate tool
```

`src/videowipe/locales/ignore.json` has two lists:

- **`paths`** — glob patterns of files never to extract from.
  `src/videowipe/detect.py` is ignored: its Chinese keyword tables are
  *user-input vocabulary* (intents the user may type), not user-visible text.
- **`strings`** — exact source strings never to translate.

## Commands

All commands are also exposed as `make` targets. Run them from the
repository root.

| Command | Make target | Purpose |
| --- | --- | --- |
| `python scripts/i18n_sync.py extract [--json]` | `make i18n-extract` | Print every translatable source string with its `file:line`. Sources: `web/index.html` (text, attributes, `<script>` literals and CSS `content:` strings), other `web/*.js` files, and Python string constants under `src/videowipe`. |
| `python scripts/i18n_sync.py report` | `make i18n-report` | Per locale: total / translated / untranslated / obsolete, and the untranslated list. |
| `python scripts/i18n_sync.py update` | `make i18n-sync` | Sync each catalogue: add new strings as `""`, move disappeared keys to `obsolete` (value kept), restore a key from `obsolete` if it reappears. Never overwrites a non-empty translation. |
| `python scripts/i18n_sync.py check` | `make i18n-check` | Exit 1 if any locale has untranslated strings or a value whose `{n}` placeholder set differs from its key. |
| `python scripts/i18n_sync.py new-locale <code> <name>` | — | Create an empty catalogue and populate it via `update`. |
| `python scripts/i18n_sync.py translate --locale <code> [--model M] [--batch N] [--dry-run]` | `make i18n-translate` (with `LOCALE ?= en`) | Fill empty values using the Anthropic Messages API. |

The extractor is deterministic, so running it on an unchanged tree produces a
stable string set and the catalogue diffs stay small.

### How `translate` behaves

`translate` batches the empty-valued keys and asks the model (default
`claude-sonnet`) for a JSON object mapping each source string to its
translation. The prompt describes the product, the target language and the
register (concise UI English, UK spelling for `en`), and includes a small
sample of already-translated entries as a glossary so terminology stays
consistent. It:

- only fills **empty** values — it never overwrites an existing translation;
- validates each returned value's placeholder set against its key, and **rejects**
  entries whose placeholders do not match (leaving them empty) or that are
  missing/empty, reporting each rejection;
- reads the API base from `ANTHROPIC_BASE_URL` (default `https://api.anthropic.com`),
  and authenticates with `ANTHROPIC_API_KEY` (`x-api-key`) or
  `ANTHROPIC_AUTH_TOKEN` (Bearer);
- handles HTTP and network errors gracefully, continuing with the next batch.

Use `--dry-run` to see which batches would be sent without calling the API or
writing anything.

## Adding a language

1. `python scripts/i18n_sync.py new-locale <code> <name>` — this creates
   `src/videowipe/locales/<code>.json` with every current source string
   mapped to `""`.
2. Translate the blanks — by hand, or with
   `make i18n-translate LOCALE=<code>` (or repeat for a specific model /
   batch size), then review the output.
3. `make i18n-check` — confirm there are no untranslated strings and no
   placeholder mismatches.
4. Commit.

## Upstream-merge workflow

This is the routine after `git merge`-ing a change from upstream:

```
git merge upstream
make i18n-sync      # add new strings (as ""), obsolete the removed ones
make i18n-report    # see what needs translating and what is obsolete
# translate the blanks — by hand, or:
make i18n-translate
# review the translations
make i18n-check     # must pass before you commit
git commit ...
```

Two things to remember:

- **Untranslated strings fall back to the original Chinese.** Merging an
  upstream release that adds Chinese UI text therefore never regresses the
  English UI — the new strings simply display in Chinese until translated.
- **Obsolete entries are kept for reference.** When an upstream change removes
  a string, `i18n-sync` moves its translation from `messages` into `obsolete`
  rather than deleting it, so a later revert or reintroduction can restore it
  automatically (and a human can mine it for terminology).
